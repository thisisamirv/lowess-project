# Stored golden fixtures

These files freeze `rfastlowess`'s output for the engine paths that have no
external reference implementation, so any change — intentional or not —
appears as a reviewable diff in `git`.

| File | Engine | What is stored |
| --- | --- | --- |
| `batch_default.csv` | `Lowess()` default config | `x`, `y`, `yhat` (the default `boundary_policy = "extend"` path, which R has no analogue for) |
| `batch_intervals.csv` | `Lowess()` with `return_se`, CI/PI, derivative | `x`, `y`, `yhat`, `se`, `ci_lower/upper`, `pi_lower/upper`, `derivative` |
| `batch_robust.csv` | `Lowess()` with two outliers + robustness | `x`, `y`, `yhat`, `robustness_weight` |
| `streaming_chunked.csv` | `StreamingLowess()` | `x`, `y`, `yhat` |
| `online_full.csv` | `OnlineLowess()` full mode | `x`, `y`, `yhat` |
| `PROVENANCE.txt` | — | environment facts stamped at generation |

## Why these exist

The live comparisons in `test-validation.R` only cover what `stats::lowess`
and `stats::lm` can reproduce. These fixtures cover the rest:

- the default `boundary_policy = "extend"` (R's `lowess` has no analogue),
- intervals, standard errors, and the per-point derivative,
- robustness weights,
- the streaming and online engines (no R analogue).

They implement the srrstats **G5.4c** ("stored reference data") requirement:
`test-golden.R` re-runs each case and checks the result against the committed
CSV within a `1e-10` tolerance.

## Regeneration

The fixtures are generated by `make_reference.R`, which shares its case
definitions with `test-golden.R` via `tests/testthat/helper-golden.R`, so the
two cannot drift apart. Re-creating the files is an explicit, reviewable
operation — never something the test suite does silently in the background:

```sh
cd bindings/r
R CMD INSTALL .                        # build + install the current package
Rscript tests/testthat/fixtures/make_reference.R
git diff                               # review changes before committing
```

`make_reference.R` writes each CSV and re-stamps `PROVENANCE.txt` with the
R version, package version, platform, seed, RNG kind, and a per-file `md5`
checksum.

## Configuration recorded

All cases share one deterministic series (`n = 60`, `set.seed(20240911)`):

```r
x <- seq(-3, 3, length.out = 60)
y <- sin(x) * x + rnorm(60, 0, 0.25)
```

| Case | Config |
| --- | --- |
| `batch_default` | `Lowess(fraction = 0.67, iterations = 3L, boundary_policy = "extend", parallel = FALSE)` |
| `batch_intervals` | `Lowess(fraction = 0.3, iterations = 2L, boundary_policy = "extend", return_se = TRUE, confidence_intervals = 0.9, prediction_intervals = 0.9, return_derivative = TRUE, parallel = FALSE)` |
| `batch_robust` | `Lowess(fraction = 0.4, iterations = 5L, boundary_policy = "extend", return_robustness_weights = TRUE, parallel = FALSE)`; `y[9]` and `y[33]` get a `+4` outlier |
| `streaming_chunked` | `StreamingLowess(fraction = 0.3, chunk_size = 20L, overlap = 0L, iterations = 1L, parallel = FALSE)` |
| `online_full` | `OnlineLowess(fraction = 0.3, window_capacity = 16L, min_points = 4L, update_mode = "full", iterations = 2L)` |

## Determinism notes

- `parallel` is pinned to `FALSE` in every stored case so thread scheduling
  cannot perturb the committed values (parallel/serial equivalence is already
  covered by property tests in `test-fastlowess.R`).
- Values are written with 17 significant digits (`%.17g`), enough to
  round-trip an IEEE-754 double losslessly.
- The fixtures depend on R's default RNG (`Mersenne-Twister` / `Inversion`),
  recorded in `PROVENANCE.txt`. Regenerate on the reference platform;
  cross-platform `libm` differences in the *data generator* are far below the
  `1e-10` test tolerance.
